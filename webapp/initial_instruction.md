# 【サービス概要】
既存のリアルタイム音声翻訳アプリ「Sokuji」の、セットアップの分かりにくさ・モード選択の迷いを解消するための、ログイン必須の入口アプリ「SOKUJI Allo」

# 【サービス詳細】
- SOKUJI Alloが担当するのは「ログイン」と「モード選択（ローカルモデル or API利用）」のみ
- 言語設定・デバイス設定・チュートリアル・実際の翻訳セッションは、既存のSokuji Chrome拡張機能にすべて任せる（新規に作らない）
- モード選択が終わったら、Sokuji拡張機能へ自動的に引き継ぐ（後述）
- Electronアプリへの誘導はしない。拡張機能のみ対象
- 優先度としては、まず一連の流れ（ログイン→モード選択→拡張機能への引き継ぎ）が通しで動くデモを完成させることを最優先とする

## 拡張機能への引き継ぎ方式
- 拡張機能インストール済み: `externally_connectable`（Webページ→拡張機能へのメッセージ送信）で、選んだモード（ローカル/API）を拡張機能に自動的に渡し、拡張機能側の画面を開く
- 拡張機能未インストール: Chromeウェブストアの当該拡張機能ページへ誘導する

# 【画面枚数】
2画面のみ（Sokuji本体側で従来から持っている画面は対象外）
- ログイン画面
- モード選択画面

# 【画面詳細】
詳細仕様は `docs/spec/screens/` 配下に記載済み。

## ログイン画面（実装済み）
Googleアカウントでのログインのみ（Firebase Authentication）。メール/パスワードやその他プロバイダは対応しない。
→ `docs/spec/screens/Login.md`

## モード選択画面（実装済み・要修正）
「ローカルモデル」「API利用」を対等な2択として提示（優劣バッジなし）。
現状は選択後に自前のセットアップウィザードへ遷移する作りになっているが、今後は選択後に Sokuji 拡張機能へ引き継ぐ形に変更する。
→ `docs/spec/screens/ModeSelect.md`

## （不要になった画面）
以下は screens-only フェーズで作ったが、今回の方針転換により Sokuji 拡張機能側の既存機能と重複するため、webapp からは削除予定：
- セットアップウィザード（言語 → デバイス → 確認）
- セッション画面
- 設定画面（ただし、Firebase Authのログアウト導線だけはどこかに必要かもしれない → 要検討）

# 【データベース設計】
- 認証: Firebase Authentication（Google Sign-In）— 実装済み
- モード選択結果の永続化は現時点では不要（都度選んで拡張機能に引き継ぐだけのため）。将来的にユーザーごとの初期値を覚えさせたくなったら Firestore を検討

# 【注意事項】
- スタックは React + TypeScript + Vite + SCSS（Next.jsではない。既存Sokuji本体と合わせている）
- `webapp/` は現状、既存の `src/`（拡張機能側）から完全に独立したプロジェクト構成のまま（今回の方針転換により、モノレポ化の必要性はなくなった）
- Firebase Hosting（プロジェクト: `pantarhei-int-sandbox-prd`）にデプロイ済み
- ローカルモデルではモデルごとに対応可能言語が異なるが、今回 webapp 側では言語選択自体を扱わなくなったため、この制約は Sokuji 拡張機能側の話として引き続き考慮する
